# Frontend status — 31 August 2026

This supplements the historical 20 August handbook and backlog. Source and tests
take precedence over historical problem descriptions. This is a technical demo,
not a clinical release or proof of backend deployment.

## Changes included

- Tablet page/layout updates across login, dashboard, screening, result,
  validation, datasets, sync, account and navigation.
- FE-002 (partial): one `DiagnosisDraft` connects form values to provider state;
  name, gender and age are required. Height and weight remain required as well.
  Reset clears the draft. Backend submission of clinical metadata remains open.
- FE-003 (partial): camera and gallery use real image bytes with filename,
  detected MIME, size limit and SHA-256. PNG/JPEG and Part-10 DICOM signatures are
  recognized; this is not full image/content validation. Gallery uses an image
  picker, so DICOM selection/preview is not an end-to-end supported workflow.
- FE-013: failed inference stays on the form, reports an error and clears the
  outcome; successful inference navigates to Result. Widget tests cover both.
- Direct Result navigation without an outcome shows an explicitly labelled
  `DUMMY / DEMO — BUKAN HASIL KLINIS` example. This fallback is not restricted by
  a production flavor. Mock inference outcomes are also non-clinical.
- User-facing labels use screening. Internal `diagnosis` names/routes and API
  contracts are retained to avoid compatibility breaks.

## Remaining limitations

- `USE_HTTP` and `API_BASE_URL` are build-time defines, not remote config.
- `USE_HTTP=false` by default; mock auth and random inference must not be used
  clinically. Production flavor separation and a permanent mock watermark remain
  FE-001 work; the labelled empty-result sample does not satisfy that whole gate.
- Dashboard, validation and dataset repositories remain mock in both modes.
- Save/PDF/Print, durable screening provenance, durable doctor validation, secure
  token storage, tenant/session isolation and robust offline retry still require
  the safety gates in `tasks/FRONTEND_TEAM_BACKLOG.md`.
- Backend deployment, production signing and clinical model validation are not
  part of this frontend push.

## Verification

- `flutter analyze`: no issues.
- `flutter test --reporter expanded`: 50 tests passed, including the form golden,
  required fields, draft reset, image signature/checksum and inference failure.
- `flutter build apk --debug`: built successfully (mock/demo configuration).
- Drift code generation completed and `app_database.g.dart` has no diff.
  The existing CI command's `--delete-conflicting-outputs` flag is ignored by
  this build_runner version; generation still succeeded.
- These checks do not replace device camera testing, HTTP end-to-end testing,
  persistence/restart testing or clinical validation.

Local agent configuration, unrelated attachments, build artifacts and presentation
files are excluded from the frontend change set.
