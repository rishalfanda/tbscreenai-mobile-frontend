## Integration boundaries

- No new backend endpoint was invented. Diagnosis creates/status updates use the
  existing sync protocol; authoritative conflict snapshots use `/diagnoses/{id}`.
- The create payload currently sends the supported diagnosis fields. Clinical
  snapshots and image bytes remain durable locally; the server create contract
  still needs image/provenance support before this is a complete clinical save.
- `saved` currently means the server acknowledged the diagnosis operation. It
  does not prove that the X-ray or full clinical snapshot was persisted remotely.
- Server-only diagnoses lacking explicit non-mock provenance cannot be clinically
  validated. A local non-mock diagnosis needs its server version pulled before
  doctor review; timestamps are not substituted for version locking.
- Decision and validation audit entries are owner-scoped local evidence. No claim
  is made that these local entries have been uploaded to a backend audit service.
- APK compilation is not device installation, Keystore verification, a signed
  production release, or live-backend E2E. Export/print remain disabled.
- Existing logout/account-switch cache-clearing policy still applies. Restart
  recovery requires login as the same owner; logout intentionally clears cache.
