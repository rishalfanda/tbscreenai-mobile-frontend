## Secure-storage setup dan keputusan offline auth

- Android memakai Flutter `minSdkVersion` 24 (memenuhi minimum API 23 untuk
  dependency), dan backup aplikasi dinonaktifkan agar material secure storage
  tidak ikut Android backup.
- iOS Debug/Profile/Release memakai entitlements Keychain masing-masing.
- Offline session restore sengaja **fail-closed**. Sampai product memilih PIN
  atau biometric/local-auth policy, startup online mode menghapus token lama
  dan user wajib login kembali. Cache ber-owner tidak dibuka hanya karena token
  pernah tersimpan.
- Jangan membuat fallback token ke SQLite, SharedPreferences, log, atau source
  code jika plugin secure storage gagal.

## Migration dan rollback

Upgrade v1 ke v2 berjalan dalam transaction Drift. Pending operation dengan
`session_owner` valid dipertahankan dan diberi tenant/user/device. Operation
tanpa owner tetap disimpan tetapi dikarantina agar tidak pernah terkirim atas
nama akun yang salah. Operasi berstatus `sending` saat process crash dipulihkan
menjadi `retryable` menggunakan `client_op_id` yang sama.

Sebelum rollout:

1. Backup database aplikasi v1 dan catat versi binary.
2. Jalankan upgrade pada salinan data representatif, termasuk queue pending.
3. Verifikasi login, ownership, queue, dan pull/push terhadap environment uji.

Rollback tidak boleh sekadar memasang binary v1 di atas database v2. Restore
backup database v1 bersama binary v1. Token lama yang pernah ada di SQLite
sengaja tidak dipulihkan; user harus login ulang.
