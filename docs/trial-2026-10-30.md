- Bar judul/sidebar diperkecil 56 menjadi 48 px; target sentuh tetap 48 px.
- Verifikasi diganti pilihan bilangan bulat 0–10, lalu Confirm di bawahnya.
- Uji lengkap login → update model → screening → simpan → verifikasi → sync.

## Kontrak yang perlu diberikan Mas Amar

- API_BASE_URL dan HEALTH_URL yang terjangkau dari perangkat uji.
- OpenAPI staging serta branch/SHA yang benar-benar dideploy.
- Provisioning doctor/device sintetis melalui kanal secret; jangan commit kredensial.
- Makna skor 0–10, nama field, status setelah Confirm, aturan catatan,
  cara membaca kembali skor dan aturan konflik/revisi.
- Model asli/mock, lokasi inference (backend/perangkat), manifest/bundle,
  checksum dan versi model yang diharapkan.

Jangan memetakan skor menjadi agreed/disagreed atau menyisipkannya dalam
doctor_note. Backend main yang diperiksa hanya menerima status
pending/agreed/disagreed, tanpa field skor.

## Gap yang ditemukan

| Alur | Bukti kode / pekerjaan tersisa |
|---|---|
| Login | HTTP auth tersedia; aktivasi dan header device belum ada di frontend. Cocokkan dengan DEVICE_AUTH_REQUIRED staging. |
| Update model | ModelUpdateService memakai /models/check; tanpa URL bundle sekarang gagal eksplisit, tanpa progress simulasi atau perubahan installed version. Endpoint staging masih perlu dicocokkan. |
| Inference | Mode HTTP tersedia, tanpa fallback lokal; backend main masih run_mock_inference. Perlu bukti staging model asli atau label mock eksplisit. |
| Simpan | Clinical/image_id/provenance masuk antrean lokal terenkripsi; mock diblokir. Perlu baca balik penyimpanan server. |
| Verifikasi | UI/repository/cache/sync masih verdict status lama. Skor memerlukan kontrak tulis, baca, persistensi, dan konflik. |
| Sync | Pull sekarang mengikuti has_more/next_cursor dengan limit 500. Semua halaman dikumpulkan lalu cache dan watermark di-commit dalam transaksi yang sama. Gagal di tengah/cursor berulang/pergantian snapshot tidak mengubah cache. Push idempotent/retry tetap tersedia. |

Perbaikan lokal: `test/trial_sync_readiness_test.dart` mencakup multi-page,
retry setelah halaman lanjutan gagal, cursor hilang/berulang, watermark berubah,
logout saat pagination, serta URL bundle null/kosong/whitespace. Belum bukti E2E.

## Acceptance di perangkat dengan data sintetis

1. Login doctor pada perangkat terdaftar; refresh token tetap bekerja.
2. Unduh bundle nyata, periksa checksum, jalankan smoke test, lalu aktifkan.
   Kegagalan tidak boleh mengganti versi aktif; restart mempertahankan versi.
3. Screening gambar sintetis dari galeri/kamera; rekam versi, sumber model,
   is_mock, confidence, image_id dan provenance sesuai kontrak aktual.
4. Simpan, matikan jaringan dan restart APK; hasil dan antrean tetap tersedia.
5. Sambungkan jaringan, sync dan baca balik clinical serta referensi gambar.
6. Pilih skor 0 dan 10 pada kasus berbeda, Confirm sekali, restart dan sync;
   nilai harus sama di aplikasi dan server. Cek retry serta konflik versi.
7. Pull dataset lebih dari satu halaman tanpa kehilangan baris; watermark
   hanya maju setelah seluruh halaman berhasil.

Status lulus hanya setelah ada bukti APK/perangkat dan baca balik server.
